# Historical Evidence Interactions

사료를 퀴즈 전에 보여주는 장식이 아니라 **학생이 추론에 사용하는 도구**로 만든다.

보고는 기본적으로 한국어로 한다.

## 학습 루프

가능하면 다음을 반복한다.

1. 사료 관찰
2. 관련 특징 포착
3. 질문/판단 기준과 연결
4. 잠정 추론 기록
5. 다른 사료와 비교
6. 판정 유지·수정·보류

'맞는 곳 클릭' 하나만으로는 역사적 사고가 아니다.

## 현재 저장소 우선

기존 단일 HTML, 기존 모달, 기존 카드 UI, 기존 상태 저장 방식이 있으면 그것을 확장한다. 이 스킬을 이유로 프레임워크를 추가하거나 파일을 분해하지 않는다.

## 사료 데이터

가능한 경우 다음 역할을 분리한다.

```json
{
  "id": "src-01",
  "title": "...",
  "date": "...",
  "sourceType": "official-document",
  "provenance": "...",
  "citation": "...",
  "image": "assets/...",
  "transcript": "...",
  "studentCaption": "...",
  "teacherNote": "...",
  "verificationStatus": "verified",
  "hotspots": [],
  "claimsSupported": []
}
```

학생용 필드에 정답 문장을 숨겨 넣지 않는다.

## 고지도·이미지·문서 판독

확대가 의미 있을 때 pan/zoom과 의미 있는 영역 표시를 사용한다.

핫스팟은 역사적으로 중요한 특징이어야 한다.
- 터치/트랙패드 모두 누르기 충분한 크기
- 반복 실패 시 회복 힌트 제공
- 역사 개념이 핵심인데 정확한 픽셀 좌표를 요구하지 않음

지도에서는 명칭, 위치, 관할 표현, 이동 경로, 거리, 변화 등을 추론하게 한다. '작은 점 찾기' 자체를 과제로 만들지 않는다.

## 증거 카드

장면을 넘어 정보를 들고 가야 할 때 사용한다.

```js
{
  id,
  sourceId,
  label,
  observation,
  possibleMeaning,
  reliabilityNote,
  tags: []
}
```

**관찰**과 **해석**을 분리한다.

## 비교·분류·연결

드래그앤드롭은 배치 자체가 사고를 표현할 때만 쓴다.
- 시간 순서
- 주장 ↔ 근거
- 행위자 ↔ 이해관계
- 사료 일치/불일치
- 판단 기준 ↔ 역사 사실

단순 객관식 버튼을 드래그로 바꾸지 않는다.

## 판정 갱신

초기 판단을 했다면 덮어쓰지 말고 기록한다. 새 증거를 본 뒤:
- 유지 + 근거 설명
- 수정
- 판단 보류/불확실 표시
중 하나를 선택할 수 있게 한다.

## 확정 사실과 해석 가능성을 구분한다

수업 자료와 출처로 확정되는 사실은 '여러 해석이 모두 가능'하다는 식으로 처리하지 않는다. 열린 부분은 주로 **증거의 의미·신뢰도·비중·인과적 해석·판정 방어 방식**이다.

## 역사 검수

출시 전 각 핵심 사료/주장에 대해:
- 저장소의 출처 데이터 또는 교사 제공 자료와 직접 대조
- 제목/날짜/작성자/출처 확인
- 이미지와 전사문 일치 확인
- 번역·현대화·요약·의역을 직접 인용과 구분
- 크롭·삭제·재구성 여부 기록

저장소에 근거가 없으면 `UNVERIFIED – 교사 확인`으로 남긴다. 근거 없이 '검증 완료'라고 쓰지 않는다.

## 완료 기준

학생이 다음 네 질문에 답할 수 있어야 한다.
- 무엇을 관찰했는가?
- 어느 사료가 그것을 뒷받침하는가?
- 그것이 질문에 왜 중요한가?
- 다른 사료가 내 판단을 강화·약화·복잡화했는가?
