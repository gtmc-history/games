# History Game UI Design

역사적 분위기는 살리되 **AI가 만든 대시보드처럼 보이는 화면**을 피한다. 장식보다 정보 위계와 플레이 흐름을 우선한다.

보고는 기본적으로 한국어로 한다.

## 기존 디자인 시스템 우선

- `.agents/skills/gtmc-history-design/`이 있으면 그 시대별 팔레트·폰트·금지 목록을 이 스킬보다 우선한다.
- 저장소의 CSS 변수, 폰트, 컴포넌트, 기존 화면 톤을 먼저 읽는다.
- 사용자가 전면 리디자인을 요청하지 않으면 기존 톤을 유지한다.
- 단일 HTML이라면 디자인 개선 때문에 프레임워크를 추가하지 않는다.

## 피할 패턴

- 의미 없이 모든 것을 둥근 카드로 감싸기
- 과도한 그라데이션/글로우/유리효과
- 모든 섹션에 같은 크기의 카드 격자
- 역사적 맥락과 무관한 게임 HUD 남발
- 장식용 아이콘을 문장마다 붙이기
- 너무 많은 폰트 크기·색상·테두리
- 작은 본문과 넓은 빈 공간의 'SaaS 대시보드' 구성

## 화면 위계

한 화면에서 우선순위를 3단계 이내로 유지한다.
1. 지금 해야 할 행동
2. 판단에 필요한 역사 자료
3. 진행/보조 정보

학생이 화면을 보고 3초 안에 다음 행동을 찾을 수 있어야 한다.

## 사료 화면

- 원문/이미지가 중심
- 출처·날짜·설명은 찾을 수 있지만 자료보다 시각적으로 강하지 않게
- 확대/주석 도구는 자료를 가리지 않게
- 증거 확보 여부를 명확하게 표시

## 입력 장치

프로젝트 프로필을 따른다.
- touch-first: 안정적인 큰 터치 타깃, hover 의존 금지
- keyboard-first: 명확한 focus, 키보드 탐색 가능
- mixed: 둘 다 완주 가능

## 역사 분위기

신문, 기록실, 지도, 타자기, 공문서 등의 시각 언어를 사용할 수 있지만 텍스트 가독성과 조작성을 희생하지 않는다. 실제 사료처럼 보이는 장식 텍스트가 학생에게 진짜 사료로 오인되지 않게 구분한다.

## 반응형

- 기존 목표 기기 해상도를 먼저 확인
- 필수 버튼이 접힘 아래로 밀리지 않게
- 한국어 줄바꿈/긴 단어/숫자 표기 확인
- 세로/가로 전환이 가능한 기기라면 중요한 상태 보존

## 완료 기준

- 첫 화면에서 다음 행동이 분명함
- 장식이 역사 자료보다 강하지 않음
- 동일 기능의 컴포넌트 스타일이 일관됨
- 프로젝트 주 입력 장치에서 타깃 크기와 포커스가 적절함
- AI식 범용 대시보드 느낌보다 해당 역사 장면의 맥락이 드러남
- 시각 개선 때문에 기존 기능/배포 구조가 손상되지 않음
