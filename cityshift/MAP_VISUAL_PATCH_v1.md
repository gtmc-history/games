# cityshift 지도·비주얼 패치 v1.1

상태: 교사용 재검수 전 Visual Patch

이 패치는 DESIGN_LOCK v1.0의 Core Sequence, 사례 구조, 저장 계약을 바꾸지 않고 Presentation Layer만 수정한다.

## 0. v1.1 수정 이유

v1.0에서는 1934년 「朝鮮鉄道略図」와 목포 지형 이미지를 단순 확대·크롭한 뒤 HTML 노드를 퍼센트 좌표로 얹었다. 해당 원본은 게임 화면의 좌표계와 지리적으로 등록(georeference)되어 있지 않았기 때문에 지도와 도시 표시가 일치하지 않았다.

v1.1에서는 이 방식을 폐기한다.

- 상호작용 보드의 배경은 지리 경계 좌표가 공개된 `South Korea location map.svg`를 사용한다.
- 공개된 지도 경계값 N 38.9 / S 33.0 / W 124.5 / E 132.0과 원본 SVG 크기를 기준으로 위도·경도를 지도 좌표로 변환한다.
- 모든 도시 표시와 효과 노드는 같은 좌표 변환을 사용한다.
- 1934년 철도지도는 더 이상 상호작용 오버레이의 기준 배경으로 사용하지 않고 `역사지도 참고` 링크로만 둔다.

## 1. 좌표 등록 배경 지도

### South Korea location map.svg
- 제작자: NordNordWest
- 공개본: Wikimedia Commons `File:South Korea location map.svg`
- 설명: https://commons.wikimedia.org/wiki/File:South_Korea_location_map.svg
- 직접 파일: https://upload.wikimedia.org/wikipedia/commons/b/b2/South_Korea_location_map.svg
- 투영: equirectangular, N/S stretching 120%
- 공개 경계값: N 38.9° / S 33.0° / W 124.5° / E 132.0°
- 라이선스: CC BY-SA 3.0 (GFDL 병행)
- 게임 사용: 화면 2와 사례 1~3의 위치 등록용 배경.

## 2. 도시 좌표 기준

좌표는 현재 위치를 지도에 정확히 등록하기 위한 기준이며 역사적 인과를 의미하지 않는다.

- 대전: 36.3500, 127.3850
- 공주: 36.4500, 127.1170
- 이리: 현 익산역 일대 35.94167, 126.94583
- 구 나주읍: 금성관 일대 35.03389, 126.71694
- 광주: 35.16667, 126.91667
- 영산포: 옛 영산포역 일대 35.00528, 126.70667
- 목포: 34.79361, 126.38861

## 3. 역사 지도 취급

### 1934 「朝鮮鉄道略図」
- 공개본: Wikimedia Commons `File:1930s korea rail map.jpg`
- 설명: https://commons.wikimedia.org/wiki/File:1930s_korea_rail_map.jpg
- 사용: 당시 철도망을 확인하는 참고 자료 링크.
- 금지: 지리 등록 없이 확대·크롭한 뒤 도시 노드나 학생 인과선을 직접 겹치지 않는다.

### 장서각 1917~18년 지형도
- 대전·공주·이리·나주·영산포·광주·목포 지형도는 역사적 위치와 지형 관계 검증 자료로 유지한다.
- 원문 스캔의 production 직접 사용은 이용 조건을 별도 확인하기 전까지 보류한다.

## 4. 구현 원칙

- 지도 마커와 효과 노드는 동일한 위경도→SVG 좌표 변환을 사용한다.
- 지도 크기나 화면 폭이 바뀌면 실제 렌더된 SVG의 letterbox 영역까지 계산해 노드를 다시 배치한다.
- 목포의 `성장 시작`과 `1932 대도시 위상`은 같은 목포 좌표에 귀속시키되 버튼이 겹치지 않도록 위·아래로 배치하고 지도상의 목포 기준점은 고정한다.
- 지도는 위치 확인용이다. 철도·항만·행정 기능의 상대적 영향력을 지도 선 굵기나 도시 크기로 암시하지 않는다.
- 학생이 만드는 굵은 인과선과 배경 지도는 별도 레이어다.

## 5. 검수 필요

1. 화면 2에서 공주·대전·이리·나주·목포 표시가 실제 지도 위치와 일치하는지
2. 사례 1에서 공주가 대전의 서북쪽에 정확히 놓이는지
3. 사례 2에서 이리가 광주·나주·영산포보다 북쪽에 있고, 나주와 영산포가 가까운 별도 지점으로 읽히는지
4. 사례 3에서 목포 노드가 서남 해안 위치에 등록되는지
5. 1366×768 / 1024×768 / 모바일에서 resize 뒤에도 표시가 이탈하지 않는지
6. 인과선 재계산이 노드 이동 뒤 정상 작동하는지

이 검수가 끝나기 전 `published` 전환은 하지 않는다.
