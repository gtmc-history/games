## 1. GAME DESIGN LOCK

### Historical Discovery
> 조선시대에 중심지였다는 사실만으로 일제강점기의 도시 성장을 예측할 수 없다. 새로운 교통망을 비롯한 식민지기의 변화가 기존 도시의 위계를 다시 만들었고, 도시마다 그 이유도 같지 않았다.

### 3행 설계 게이트
- **발견 한 문장**: 기존 도시의 크기와 지위만으로 근대 도시의 성장을 설명할 수 없으며, 새로운 교통망과 다른 역사적 조건을 함께 봐야 한다.
- **플레이 동사**: 예측한다 · 대조한다 · 재판단한다
- **행동의 이유**: 먼저 자신의 예측을 남긴 뒤 실제 변화와 새 자료를 만나야, 철도 하나를 정답으로 외우는 대신 어떤 조건이 도시의 성장과 쇠퇴를 설명하는지 자신의 인과 설명을 수정하게 되기 때문이다.

### Player Verb
예측한다 / 대조한다 / 재판단한다

'가설을 세운다'는 `재판단한다`에 포함한다. 지도 확대와 카드 넘기기는 인터페이스 동작이며 Player Verb가 아니다.

### Core Sequence
`조건만 보고 초기 판단 → 지명·실제 변화 공개 → 원인 가설 설정 → 단계적 자료 공개 → 가설 수정 → 세 사례 대조 → 처음의 설명 다시 쓰기`

사례 단위로 Loop가 돌고, 세 사례를 거치며 `단일 규칙 형성 → 규칙 붕괴 → 조건의 복수화 → 도시별 설명 차이 확인`의 Sequence가 위에 놓인다.

### Game Fit
- **게임으로 만드는 이유**: 핵심이 정답을 읽는 것이 아니라 자기 예측이 무너지고 설명을 다시 만드는 경험이기 때문이다. 활동지는 이 순서를 강제하지 못한다.
- **재미의 근거**: 판단이 새 증거로 뒤집히는 경험

### Engagement Hook
1. "내가 고른 곳이 실제로 성장했을까"
2. "왜 내 규칙이 나주에서 깨지는가"

### Primary Mechanic
**인과 모델 구성(Causal Model Construction) — Evidence Board 패턴 활용**
학생은 도시 변화의 원인 후보를 연결하고, 새 자료에 따라 기존 연결을 유지·수정·유보·제거한다.

### Secondary Mechanic
**최소 Belief Updating** — 확신도 게이지 없음. 첫 판단을 원문 그대로 보존했다가 종료 시 재제시.

### Presentation Layer
지도(자체 SVG 약도) + 카드. 지도 타일(Leaflet/OSM 등) 사용 금지.

### State Variables

| State | 의미 |
|---|---|
| `initialPrediction` | 지명 공개 전 첫 판단과 그 이유(원문 보존, 수정 불가) |
| `caseHypothesis` | 각 사례에서 현재 학생이 생각하는 변화 원인 |
| `causalLinks` | 학생이 만든 원인→변화 연결 |
| `evidenceSeen` | 이미 공개된 자료 목록 |
| `caseExplanation` | 사례별 마무리 설명 |
| `finalModel` | 세 사례 비교 후 다시 쓴 도시 성장 설명 |
| `unresolvedClaims` | 끝까지 근거 부족으로 유보한 설명 |

**`causalLinks` 스키마**
```text
{
  cause:     원인 카드 ID,
  effect:    결과 노드 ID,
  status:    가설 | 근거확인 | 유보 | 철회,
  evidence:  [사료 ID],
  timeScope: 적용 시기 (예: "1897~", "1914~", "미상")
}
```

예시:
```text
개항 → 목포 성장 시작              | 근거확인 | S11        | 1897~
철도 → 목포 성장 강화              | 유보     | S13        | 1914~
관찰부 광주 설치 → 나주 위상 변화  | 유보     | S09a,S09b  | 미상
```

**상태 전이**
`가설 연결 → 자료 도착 → 유지 / 다른 원인 추가 / 판단 유보 / 연결 철회`

- 새 자료가 와도 기존 연결을 지우는 것이 아니라 설명을 확장할 수 있다.
- 첫 가설이 어긋나도 즉시 실패 처리하지 않는다 (Fail Forward).
- 자료가 인과를 직접 진술하지 않으면 최종 상태는 `유보`다. `철회`나 `연결 없음`으로 처리하지 않는다.

**사용하지 않는 State (잠금)**
역사 이해 점수 / 도시 성장 점수 / 철도 영향력 % / 행정 영향력 % / 확신도 0~100 / 정답 연결 개수

### Meaningful Choice
- **판단 정보**: 사례별로 §6에 명시. 선택 전에 반드시 화면에 있다.
- **선택 간 실질적 차이**: 이후 학생이 다음 자료를 볼 때 가지고 있는 설명 구조가 달라진다.
- **위장 객관식 아님**: 각 사례의 선택지 전부가 현재 확보된 자료와 충돌하지 않는다. 유일한 예외는 사례 3에서 "철도가 목포의 성장을 시작시켰다"이며, 이는 시점상 성립하지 않으므로 선택지에서 제외한다.

### Consequence
즉시 — 연결 상태와 근거 배지 변화 / 지연 — 다음 사례에 들고 가는 원인 카드와 규칙 / 판단 변화 — `finalModel`과 `unresolvedClaims`

### Replayability
불필요. 자료가 고정이고 산출물은 학생의 모델이다. 단 재시작(상태 초기화)은 반드시 동작해야 한다.

### 기존 게임과 가장 가까운 구조
`1919, 무엇이 달라졌나` / `그날, 아무도 몰랐다 1945` (판단 갱신 계열)

### 구조적 차이
두 게임은 확신도를 조절한다. 이 게임은 **연결을 만들고 끊고 시기를 붙인다.** 산출물이 확신도 궤적이 아니라 학생이 그린 세 장의 인과 지도다.

### 기각된 대안
- B안 「같은 도시, 두 개의 거리」 — 후속 예비. 게임 후 발문으로 연결
- C안 「토막 대책 절차」 — 1차 자료 확보까지 동결
- Belief Updating을 Primary로 — 계열 중복
- Evidence Evaluation을 Primary로 — `대한제국 1897`과 중복, 자료 평가가 도시 이야기를 밀어냄
- 학생이 철도 노선을 놓는 Spatial Strategy — 총독부 역할 대행. SENSITIVE §1·§2 위반

### Prediction kill rule
세 사례가 모두 사실상 `철도 개통 → 성장`으로 수렴하면 본선에서 내린다.
- 1차 판정(자료): **통과**
- 2차 판정(Gate 11 Play Audit): 세 인과 지도의 형태가 실제로 다른지 확인

## 2. 역사적 불변 원칙

1. 학생의 선택으로 실제 철도 노선, 도청 이전, 개항 시점이 달라지지 않는다.
2. 학생이 바꾸는 것은 자신의 인과 설명과 그 강도·적용 시기뿐이다.
3. 요인별 가중치를 만들지 않는다.
4. 자료로 확인하지 못한 것을 "관계가 없다"로 처리하지 않는다. 최종 상태는 `유보`다.
5. 상관·동시발생을 인과로 승격하지 않는다.
6. 지도가 잠긴 근거보다 강한 인과를 암시하지 않는다.

### 학생이 바꿀 수 있는 것
자기 인과 모델의 구성·강도·적용 시기, 판단 유보 여부

### 바꾸면 안 되는 실제 역사
1905 경부선 대전역 개통 / 1913 호남선 분기 / 1932 충남도청 이전 / 1912 호남선·군산선 개통 / 1896 전남 관찰부 광주 설치 / 1897 목포 개항 / 1914 호남선 전 구간 개통

### 후견지명 차단
- 화면 1에서 지명을 공개하지 않는다. 조건만 제시한다.
- 각 사례에서 해당 시점까지의 자료만 제공한다.
- 현재의 도시 규모·인지도를 근거로 삼는 안내 문구를 넣지 않는다.

### 화면 1 — 첫 판단 (고정 문구)

> **조건 A: 오래된 행정 중심지**
> **조건 B: 장이 서던 작은 마을**
> 앞으로 어느 쪽의 도시 위상이 더 커질 것 같습니까? 그렇게 본 이유를 한 줄로 적어 주십시오.

지명·지도·현재 도시명을 노출하지 않는다. 강 하구 포구 조건은 넣지 않는다. 항만 조건은 사례 3에서 처음 등장해야 "철도 말고 다른 성장 경로"의 효과가 산다.

### 사례별 판단 정보 (선택 전 화면에 있어야 하는 것)

**사례 1 — 대전/공주**
- 판단 정보: T1 연표, S02
- 묻는 것: `철도만으로 대전의 변화를 충분히 설명할 수 있는가 / 1932년 행정 기능 변화까지 설명에 추가해야 하는가 / 두 변화의 관계는 아직 유보해야 하는가`
- 세 답 모두 자료와 충돌하지 않는다. `철도 → 도청 이전`이라는 미확인 연결을 판정시키지 않는다.

**사례 2 — 이리 → 나주**

진입 카드 (S10a·S10b 통합, 1장):
> **호남선은 나주를 지났다. 그러나 교과서는 나주를 상대적 쇠퇴 사례로 든다.**

이리는 짧게 통과시킨다. 허허벌판에 역이 서고 도시가 생긴 사례라 연결이 하나로 깨끗하며, **이 굳히기가 나주의 반전을 위한 준비**이므로 생략하지 않는다.

자료 도착 순서:
1. 진입 카드 → 학생이 연결하거나 유보 → **S09 도착**
2. S09a·S09b 통합 카드 → 학생이 연결하면 "연결은 자료에 미진술" 배지 자동 부착 → `유지한다 / 아직 판단하지 않는다` → **S16 도착**
3. S16 도착과 함께 영산포 노드 활성화 → 학생이 `나주 = 하나의 결과` 모델을 스스로 수정

필수 Core Play 카드 3장. 학생에게 "중심이 영산포로 이동했다"를 고르게 하지 않는다.

**사례 3 — 목포**

진입 문구:
> **목포는 1932년 전국적인 대도시가 되었다. 지금까지 사용한 설명을 여기에도 적용해 보십시오.**

앞 사례에서 만든 `철도` 카드를 손에 들려주되 **연결은 선택**이다. 철도를 긋지 않고 `아직 판단하지 않는다`를 골라도 진행된다. 현재 모델 제출이 S11 도착 트리거다.
- 철도를 그은 학생: `timeScope` 불일치가 드러난다
- 유보한 학생: 정답 피드백 없이 새 자료로 모델을 만들 기회를 받는다

묻는 것: `철도 → 목포 성장 강화` 링크를 추가할 것인가, 근거가 부족하므로 유보할 것인가.

## 7. UI / Presentation

### 시점
현대 탐구자. 당대 인물 역할극 없음.

### 지도 범위 — 2층 구조
- **화면 2·6 (도입·결과)**: 전국 약도. 비교 프레임과 내비게이션 역할. 플레이보드가 아니다.
- **화면 3·4·5 (본 플레이)**: 사례별 지역 약도

| 사례 | 범위 | 필수 노드 |
|---|---|---|
| 1 | 충남 축약 | 공주, 대전, 경부선, 호남선 분기 |
| 2 | 호남 내륙~서남부 | 이리, 나주읍, 영산포, 광주, 호남선 |
| 3 | 전남 서남 해안 | 목포, 항만, 철도 도착점 |

**사례 3 약도에서 영산강을 그리지 않는다.** 나주-목포 축이 시각적으로 암시되면 자료가 진술하지 않는 인과를 지도가 대신 말하게 된다. 이 관계는 게임 후 발문에서만 다룬다.

### 화면 문법 — 2분할
**좌: 인과 보드(약도 + 학생이 만든 연결선) / 우: 카드 서랍(원인 카드, 도착한 자료)**

하단 고정 영역을 두지 않는다. 연결 상태는 선 자체에 붙이고, 하단은 한 줄 상태바로만 둔다(예: 연결 3개 · 유보 1개).

이유: 학생의 인과 모델이 화면의 가장 큰 영역을 차지해야 Primary Mechanic과 UI가 일치한다. 3분할은 가로 Chromebook에서 각 영역을 눌러 태블릿 최소 크기 기준을 깨뜨린다.

### 레이어 분리
- 철도·강·해안선: 얇은 회색, 배경, 탭 불가
- 인과선: 굵은 선, 전경, 탭하면 상태 메뉴
- 원인 카드: 지도 위에 올리지 않고 바깥 여백에 배치. 도시 노드로 선을 긋는다

### 연결 방식
**탭-탭.** 드래그를 쓰지 않는다. 태블릿 오작동이 적고 선 수정과 상태 버튼 부착이 쉽다.

### 근거 배지 (문구 고정)

| 배지 | 의미 | 표시 |
|---|---|---|
| **자료에 연결이 명시됨** | 해당 자료가 이 관계를 명시적으로 연결 | 실선 + 사료 ID |
| **연결은 자료에 미진술** | 두 사실은 확인되나 관계는 미진술 | 점선 + 배지 |
| 시기 | `timeScope` | 선 끝에 "1897~" 형태 |

실선/점선은 **보조 표현**이며 텍스트 배지가 반드시 함께 있어야 한다. 점선을 '틀린 선'으로 읽지 않도록 첫 등장 때 한 번만 짧게 설명한다. 정오를 암시하는 색을 쓰지 않는다.

### 선 탭 메뉴
`이 설명을 유지한다 / 다른 원인을 추가한다 / 아직 판단하지 않는다`

세 버튼을 항상 띄우지 않는다. 현재 상황에서 가능한 행동만 노출한다. 예를 들어 S09 연결 직후에는 `유지한다 / 아직 판단하지 않는다` 두 개만.

### 진행 버튼 문구
`다음`을 쓰지 않는다. 자료 도착의 트리거는 학생의 행동이다.

> **이 설명을 유지하고 자료를 더 본다**
> **판단을 유보하고 자료를 더 본다**

두 버튼은 서로 다른 자료를 여는 분기를 만들지 않는다. 자료는 동일하게 도착하며 차이는 **학생의 판단 상태가 보존되는 것**이다.

### 텍스트 예산 (잠금)

| 항목 | 한도 |
|---|---|
| 카드 제목 | 12~16자 |
| 카드 앞면 본문 | 45~60자 |
| 한 번에 도착하는 카드 | 기본 1장, 최대 2장 |
| 동시에 펼쳐진 자료 | 최대 4장 |
| 출처·추가 설명 | 카드 하단 `자료 정보` 탭으로 펼침 |
| 필수 읽기 카드 | 사례당 3~4장 |

출처명·사료 ID·긴 설명을 카드 앞면에 넣지 않는다. 앞면에는 판단에 필요한 사실만.

표기 형식:
> **내 설명:** 철도만으로는 부족하다. 이후 행정 기능 변화도 함께 봐야 한다.
> **확인된 사실:** 1905 대전역 개통 · 1913 호남선 분기 · 1932 충남도청 이전

중앙 문구 (입력 요구 없음):
> **세 도시의 변화는 하나의 규칙으로 설명할 수 있었습니까?**

### 화면 7 — 처음의 규칙을 다시 쓰기

좌: `initialPrediction`과 이유를 **수정 불가 원문 그대로**
우: 자유 입력. 짧은 문장 시작점만 제공하고 필수 단어를 요구하지 않는다.

> **일제강점기의 도시 변화는 __________만으로 설명할 수 없고, …**

하단 별도 영역 — **끝까지 남은 판단 유보** (`unresolvedClaims`):
> 관찰부의 광주 설치가 나주의 상대적 위상 변화에 어떤 영향을 주었는가 — 직접 연결 자료 미확보
> 1914년 이후 철도가 목포 성장에 어느 정도 기여했는가 — 직접 연결 자료 미확보

**점수·등급·정답률을 넣지 않는다.** 결과는 "모든 원인을 밝혀냈다"가 아니라 무엇을 설명할 수 있고 무엇을 아직 말할 수 없는가를 보여준다.

### 종료 조건
화면 7에서 `finalModel` 제출. 재시작 시 모든 State 초기화.

## 10. 게임 후 발문

게임을 하나 더 시작하지 않는다. **자료 전환 화면 한 장 + 발문 하나.**

제목:
> **도시가 성장했다. 그런데 누구의 도시였을까?**

좌 — S17 (여기서 처음 사용):
> 목포 개항 이후 일본인 지주층이 형성되었고, 영산포에는 일본인 시가지가 만들어졌다.

우 — 교과서 48·50쪽:
> 도시 문화는 일본인과 일부 한국인만 누릴 수 있는 특권이었다. 청계천을 중심으로 북촌과 남촌이 나뉘었고, 그 일대에는 토막촌도 있었다.

발문:
> 지금까지 우리는 '어떤 도시가 성장했는가'를 추적했습니다. 그렇다면 도시의 성장은 그 안에 사는 모든 사람에게 같은 변화를 의미했을까요? 두 자료에서 다음 수업에 더 확인하고 싶은 차이를 하나 적어 봅시다.

학생에게 "아니다"를 쓰게 하지 않는다. 무엇이 달랐는지 구체적으로 집어내게 하는 쪽이 B안과 연결된다. 농촌은 이 발문에 넣지 않는다.

## 11. 데이터 계약 (잠금)

현행 `game_results` 구조를 따른다. 최상위에 `class`, `game`, `choices`, `comment`, `timestamp`를 두고 게임별 데이터는 `choices` 안에 넣는다.

```text
game = "cityshift"

choices:
  version
  record_type = "result"
  result_id              # UUID. 중복 제출 guard
  initial_prediction     # "A" | "B"
  initial_reason         # 자유 입력
  case_models
    daejeon_gongju
      final_links[]
      summary            # 한 줄 요약 문자열
    iri_naju
      final_links[]
      summary
    mokpo
      final_links[]
      summary
  unresolved_claims[]
  final_model            # 원본 보관
  durations_ms
    case1 / case2 / case3
  completed_at

comment = final_model
```

`final_links[]` 각 항목은 `causalLinks`의 핵심 필드만 저장한다.

```text
cause / effect / status / evidence[] / timeScope
```

### `summary` 필드를 두는 이유

`final_links[]`는 구조화된 배열이라 generic renderer 화면에서는 객체 덩어리로만 보인다. 사례별 한 줄 요약을 함께 저장하면 교사가 대시보드에서 바로 읽을 수 있고, 세 요약이 서로 다른지 훑는 것만으로 **Prediction kill 2차 판정**이 된다.

예시:
```text
daejeon_gongju : "철도 유지 + 행정 추가 / 유보 0"
iri_naju       : "철도 철회 / 영산포 추가 / 유보 1"
mokpo          : "개항 1897~ 확정 / 철도 1914~ 유보"
```

custom renderer는 만들지 않는다. 첫 수업 사용 후 교사가 실제로 무엇을 보고 싶어 하는지 확인한 뒤 결정한다.

### `comment = final_model`의 조건

이 게임에는 별도 소감 입력이 없어 `comment`가 비어 있다. 따라서 최종 설명을 여기에 넣어도 결과와 소감의 분석 의미가 섞이지 않는다. **이 조건이 깨지면 계약도 바뀐다.** §12의 금지 항목 참조.

### 저장하지 않는 것

`evidenceSeen`, 카드 열람 순서, 클릭 횟수, 지도 확대 여부 등 일시적 UI 상태. 이름·학번 등 개인정보 입력을 유도하지 않는다.

### 저장 실패 처리

저장 실패가 완주를 막지 않는다. 중복 전송을 `result_id`로 막는다. fetch의 HTTP 오류를 확인한다.

### migration1938 / gyeongjecheje 건

현재 main의 manifest와 트리에서 이 두 slug가 확인되지 않는다. `economy1930`이 `gyeongjecheje`의 현행 slug일 가능성이 있으나 **이름이 유사하다는 것 외의 근거는 없으며 추정이다.** 로컬 working tree, 다른 branch, 미merge 작업일 수 있으므로 "없다"고 결론 내지 않는다.

**설계에 미치는 영향**: 이 게임에서 농촌 파트를 제외한 근거가 "두 게임이 담당한다"였다. 게임 설계는 그대로 유지하되, 두 게임이 학생이 실제 플레이할 수 있는 상태가 아니라면 **12차시 수업 계획에서 농촌을 게임 밖 활동으로 반드시 배치해야 한다.** 그렇지 않으면 12차시에서 농촌이 비게 된다. 이는 수업 설계 항목이며 DESIGN_LOCK을 되돌릴 사유는 아니다.
