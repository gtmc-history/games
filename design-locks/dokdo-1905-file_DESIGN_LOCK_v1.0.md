## 1. GAME DESIGN LOCK

### Historical Discovery
> 독도의 역사적 의미는 한 개의 유명한 사료나 구호로 완성되는 것이 아니라, 서로 다른 시점·주체·문서 성격의 기록을 연결하고 각 사료가 말할 수 있는 범위를 구분할 때 더 정확하게 설명할 수 있다.

### 3행 설계 게이트
- **발견 한 문장**: 독도 관련 역사적 설명은 단일 사료의 존재가 아니라, 여러 기록의 범위와 관계를 검토하면서 정교해진다.
- **플레이 동사**: `조사한다 → 판단한다 → 수정한다`
- **행동의 이유**: 학생은 청소년용 디지털 전시를 공개하기 전에 실제 기록으로 문장을 검수해야 하며, 새 자료가 들어올 때마다 이전 설명을 그대로 둘지 고칠지 결정해야 한다.

### Player Verb
- 조사한다
- 연결한다
- 판단을 수정한다 / 편집한다

### Core Loop / Core Sequence
- 유형: **Investigation Sequence with Optional Research Hubs**
- 구조: `문제 문장 직접 검수 → 1905 핵심 사료 정독 → 필요하면 보조자료 선택 조사 → 1877 기록·지도 역추적 → 1900 행정개편·석도 보류 → 석도/1905 맥락에 필요한 자료 선택 조사 → 1906 후속 기록 정독 → 이전 판단 수정 → 실제 열람 자료만 연구 보드에 연결 → 전시문 편집`
- 핵심 사료 4묶음은 모든 학생이 만나지만, 나카이 청원·시마네현 고시·니타카 일지·쓰시마 일지·현대 지명 연구·현재 일본 정부 설명 등은 **전부 열람하지 않는다.** 질문에 따라 학생이 선택한다.

### Game Fit
- 이 주제를 게임으로 만드는 이유: 새 자료가 공개될 때마다 이전 판단의 강도와 문장을 바꾸는 과정 자체가 역사 탐구의 핵심이기 때문이다.
- 다른 수업 형식보다 적합한 이유: 기존 독도 교재가 사료 확인과 반박문 작성에 강점이 있다면, 이 게임은 **판단 이력을 상태로 기억하고 이전 문장을 실제로 다시 열어 수정**하게 만들 수 있다.

### Engagement Hook
- 시작 1분 안에 문제 문장에서 검수가 필요한 표현을 직접 표시하는 즉시 조작
- 1905년의 문제 문장으로 시작해 이전·이후 기록을 거꾸로 추적하는 궁금증
- `석도`와 `외 1도`처럼 바로 답을 주지 않는 식별 미스터리
- 새 자료가 기존 설명을 흔드는 Belief Updating
- 마지막에 자기 전시 패널이 완성되는 편집 성취

### Primary Mechanic
- **Narrative Investigation**
- 핵심 조작 원칙: 요약 답안 버튼을 고르는 대신 **본문·지도에서 단서를 직접 추출**하고, 추출한 메모를 이후 장면에서 재사용한다.

### Secondary Mechanic
- Document-driven Gameplay
- Belief Updating / Uncertainty
- Evidence Board
- Editorial / Creation Simulation
- Progressive Disclosure
- Fail Forward

### Presentation Layer
- Visual Novel — **최소 사용. 없어도 Core Gameplay가 이해 가능해야 함.** 문제 제기·자료 도착·판단 재검토·결과 승인에만 2~4문장씩 사용한다.
- Selective Research Archive — 질문별 보조자료를 고르고, 충분하다고 생각하면 더 열지 않고 판단할 수 있는 자료실
- Document Desk
- **고정 시간축형 Evidence Board**
- 최종 전시 편집 UI

### State Variables
- `course_lens`: 한국사 / 동아시아사 / 독도교육
- `initial_marked_phrase`
- `initial_judgment`
- `draft_history[]`
- `evidence_seen[]`
- `outside_one_status`
- `seokdo_status`

- `selected_exhibit_sources[]`
- `final_panel`

### Meaningful Choice
- 판단 정보: 각 선택 전 원사료 또는 출처가 명시된 현대 자료를 제공한다. 학생 화면에는 A/B 등급이나 `직접 근거/배경 맥락` 같은 정답 역할표를 미리 표시하지 않는다.
- 선택 간 실질적 차이: 어떤 보조자료를 실제로 읽었는지, 판단 이력, 연구 보드에 나타나는 카드, 최종 전시문 후보와 근거 강도에 영향을 준다.
- 이후 영향: 이전 메모가 재노출되고, 학생의 수정 궤적이 엔딩에 남는다.
- 위장 객관식 여부: 사실형은 정오가 있을 수 있으나, 핵심 해석 선택은 `근거 강도/한계/보류`로 피드백한다. 같은 형태의 3지선다를 연속 반복하지 않는다.

### Consequence
- 즉시: 자료 해금, 메모 갱신, 연결선 생성/경고, 문장 블록 교체
- 지연: 과거 판단 재노출, 최종 패널 후보 변화
- 판단 변화: 초안 v0 → v1 → v2 → 최종안 비교

### Replayability
- 불필요(기본 수업)
- 이유: 한 차시에서 판단 변화 경험을 완결하는 것이 우선. 향후 `핵심 사료 3개만 골라 전시하기` 챌린지 모드는 별도 확장 가능.

### 기존 게임과 가장 가까운 구조
- `1919, 무엇이 달라졌나`의 Belief Updating
- `발해에서 고구려의 DNA를 찾아라`의 Narrative Investigation / Evidence Board
- `대한신문 1907`의 Editorial Simulation

### 구조적 차이
- 기존 게임과의 동작 중복은 허용한다.
- 이번 게임의 차별 기준은 **기존 독도 교재 대비**이며, 핵심 차이는 `사료 학습→반박문`이 아니라 **불완전한 전시문→자료 추적→판단 갱신→자기 전시물 완성**이라는 서사·시스템 결합에 있다.

## 2. 역사적 불변 원칙

1. 1877·1900·1904·1905·1906의 실제 문서·사건은 플레이어 선택과 무관하게 고정되어 있다.
2. 학생은 역사 사건을 바꾸지 않고 **자신의 해석·근거 선택·전시문**만 바꾼다.
3. 원사료의 직접 문구와 후대의 식별·정부 해설·학술 연구를 섞지 않는다.
4. 러일전쟁과 1905년 편입의 관계를 단일 원인으로 고정하지 않는다.
5. 현대 영유권의 국제법적 최종 판결을 게임의 정답으로 만들지 않는다.
6. `해석층`이라는 이유로 모든 해석을 동등하게 취급하지 않는다. 자료에 의해 더 잘 지지되는 해석과 근거가 부족한 해석을 구분한다.

### 학생 행동이 바꿀 수 있는 것
- 보조자료 조사 여부와 순서
- `외 1도` / `석도`에 대한 임시 메모와 보류 여부
- 자료 관계의 강도 태그
- 선택하는 핵심 전시 사료
- 최종 전시문과 주의 문구

### 바꾸면 안 되는 실제 역사
- 사건: 1905.1.28 일본 내각 결정, 1905.2.22 시마네현 고시, 1906 대한제국 측 보고·지령 등
- 인과: 특정 학생 선택으로 위 사건이 발생하거나 취소된 것처럼 만들지 않는다.

### 후견지명 차단
- 플레이어는 현대의 연구 인턴이므로 후대 자료 열람 자체는 가능하다.
- 대신 각 사료 화면에서는 **그 문서가 작성된 시점의 직접 문구**와 현대 해설을 분리한다.

## 5. 민감 주제 체크

- 적용 대상: **예** — 제국주의·영토·국권 침탈과 연결된 민감 역사
- 학생의 Agency: Inquiry + Interpretive + Editorial Agency
- 폭력·피해 재현: 없음. 전쟁은 구조·기록·군사 통신 맥락으로 다룸.
- 실존 인물: 나카이·심흥택 등은 문서 속 행위자로만 다룸. 내면·감정 창작 없음.
- 생성형 AI 역사 화자: 사용하지 않음.
- 저항/협력 이분법: 해당 없음.
- 주제 고지: 시작 화면에서 `독도 관련 역사 사료와 한·일 정부 해설을 비교하는 활동`임을 안내.
- 학생 개인 경험 공개 위험: 없음. 개인 정치·가족사 공개 요구 금지.
- 가공 인물 대표성: 현대 연구원·학생 인턴·전시 기획자는 **Gameplay 기능용 가공 인물**이며 역사적 집단 대표자로 설정하지 않는다.

### 콘텐츠 화면 고정 규칙
- `지금 밝혀야 할 질문`과 `이번 장면에서 끝내야 할 일 1·2·3`을 스크롤 전 영역에 둔다.
- 학생이 판단해야 할 자료 역할·관계는 자료 카드 설명이나 버튼 문구에서 미리 답으로 알려주지 않는다.
- 핵심 사료의 근거 추출은 요약 답안 버튼이 아니라 **본문 구절 선택/표시**를 기본으로 한다.
- 핵심 원사료 카드에는 `자료 여권 / 읽기 전 맥락 / 원문·현대어 / 읽기 도움`을 제공한다.
- 보조자료는 기본 닫힘이며, 한 번에 긴 문서 2개를 넘기지 않는다.
- 완료 조건은 체크리스트로 표시하고, 충족되지 않으면 다음 행동 버튼이 열리지 않는다.

### 씬별 Engagement 점검
- S0: 설명 전에 조작한다.
- S1: “현재 설명과 당대 원문이 같은가?”라는 출처 미스터리를 만든다.
- S2: 1905의 설명을 흔드는 첫 반전을 준다.
- S3: 답이 아니라 `추가 근거가 필요하다`는 미해결 상태를 만든다.
- S4: 같은 1904년 자료라도 **명칭 근거**와 **시대 맥락**이 다름을 손동작으로 분리한다.
- S5: 새 문제를 푸는 것이 아니라 **내가 전에 쓴 문장을 실제로 고친다.** 수정 전에 `명칭 사용 정보 / 행정 소속 표현 / 중앙정부 대응` 새 근거 트레이를 확인한다.
- S6: 자유 배치보다 관계 판단에 시간을 쓴다.
- S7: 타이핑 부담 없이 자기 결과물을 완성한다.

### 보조자료 단계 공개 규칙
- S1의 A09/A08, S2의 G02, S3의 M02, S4-B의 B01은 기본 닫힘이다.
- 학생이 `추가 자료 필요` 또는 힌트를 요청할 때만 연다.
- 보조자료를 열지 않아도 핵심 Sequence는 완주할 수 있어야 한다.

## 7. UI / Presentation

### 시점
- **현대 탐구자**: 고등학생 청소년 연구 인턴

### 화면 문법
- 공통 사료 화면은 `지금 밝혀야 할 질문 → 이번 장면에서 끝내야 할 일 1·2·3 → 자료 여권 → 읽기 전 맥락 → 원문/학생용 현대어 → 읽기 도움 → 작업 공간 → 완료 조건` 순서를 고정한다.
- Visual Novel 대화는 선택적으로 `문제 제기 / 장면 전환 / 새 자료 도착`에만 사용한다. **대화를 꺼도 핵심 Gameplay와 지시가 이해되어야 한다.**
- 핵심 사료를 한 줄 요약으로만 제시하지 않는다. 원문 또는 원문 이미지와 함께 충분한 맥락을 제공한다.
- 한 장면에서 동시에 펼쳐진 긴 문서는 최대 2개다. 나머지는 `추가 자료 열기`로 단계 공개한다.
- 동일한 버튼 선택 UI를 2씬 이상 연속 반복하지 않는다.
- 다음 장면 버튼은 `다음`이 아니라 `1905년 원문과 비교한다`, `1900년 메모를 다시 연다`처럼 실제 행동을 말한다.

### Diegetic UI
- 필요한가: 예
- 실제 Gameplay 기능: 연구실 메신저/검수 보류 문서/자료함/연구 보드가 상태를 저장하는 실제 조작 화면이 된다.

### Visual Novel 사용 시
- 대화의 기능: 문제 제기, 다음 조사 이유 생성, 새 자료 도착, 판단 재검토, 결과 승인. 교과 내용을 대신 설명하지 않는다.
- 대화량: 전체 플레이의 10% 이하, 한 Beat 2~4문장.
- 사용 Beat: S0 시작 / S1→S2 전환 / S3 석도 발견 / S5 새 보고 도착 / S7 편집 진입 / 결과.
- 대화 아래 Gameplay: 문서 밑줄, 출처 비교, 지도 단서 선택, 이전 메모 수정, Evidence Board 관계 지정, 문장 블록 편집

### Evidence Board
- 자료 카드는 자유 이동시키지 않고 기본적으로 연도 위치에 고정한다.
- Gameplay는 카드 배치가 아니라 **자료 사이 관계 라벨을 결정하는 것**이다.
- 태블릿에서 드래그 정확도가 낮아도 핵심 플레이가 막히지 않도록 탭→연결 방식 지원.

### 캐릭터 기능
- **한 연구원**: 사료 범위·출처 검수
- **서윤(학생 인턴)**: 학생이 가질 만한 직관·의문 제기
- **박 기획자**: 청소년용 가독성·전시 제약 제시
- 캐릭터 호감도·연애·도덕 점수 없음.

## 8. 학습지 / API 의존성

### Worksheet
- 기본 플레이에 필요: **아니오**
- 사용한다면 역할: 게임 후 토론·최종 전시문 비교용 선택 보조지

### External API
- 없음
- 모든 핵심 사료·대사·피드백은 정적 데이터로 포함한다.
- 외부 원문 링크는 `원문 보기` 보조 기능으로만 제공하고, 수업 핵심 흐름은 오프라인 캐시/정적 asset만으로 완결한다.

## 9. 결과 화면

- 선택 궤적: 첫 밑줄·판단 → 1877 이후 → 1900 보류 → 1904 보강/맥락 → 1906 재판단
- 판단 변화: draft v0/v1/v2/final 비교
- 결과물: 청소년용 독도 디지털 전시 패널
- 남은 불확실성: `이 자료만으로 말할 수 없는 것` 1개 표시
- 점수 사용 여부와 근거: **점수 사용 안 함**. 사실 오독은 즉시 교정하되 해석·평가를 점수화하지 않는다.
- 결과 피드백 축:
  - **출처 구분** — 당대 원문과 현대 해설을 구별했는가
  - **근거와 표현의 강도** — 사료가 감당하는 범위보다 강하게 쓰지 않았는가
  - **역사적 맥락 연결** — 사실·명칭·군사통신 맥락을 한 종류의 근거처럼 섞지 않았는가

## 10. 게임 후 발문

> 같은 사료를 사용하더라도 `사료가 직접 말하는 것`, `여러 자료를 연결해 해석한 것`, `오늘날 우리가 평가하는 것`은 어떻게 달라지는가? 네 최종 전시문에서 이 세 층을 하나씩 찾아보자.

한국사 확장 발문:
> 1905년의 독도 편입을 대한제국 국권 침탈의 흐름 속에서 설명하려면 어떤 맥락 자료를 더 연결해야 할까?

동아시아사 확장 발문:
> 러일전쟁과 일본의 제국 팽창 속에서 영토·군사·통신망은 어떻게 연결되고 있었을까?

## 11. 데이터 수집

수집 목적 없는 값은 저장하지 않는다. 개인 식별정보, 자유서술 원문, 정치적 성향 추정값은 수집하지 않는다.

| key | 의미 | 분석 용도 |
|---|---|---|
| `course_lens` | 한국사/동아시아사/독도교육 모드 | 모드별 완료 시간·선택 흐름 비교 |
| `scene_elapsed[]` | 씬별 체류 시간 | 지나치게 긴 읽기/조작 구간 탐지 |
| `hint_used[]` | 사실 확인용 힌트 사용 여부 | 난이도 튜닝 |
| `revision_count` | 이전 판단을 수정한 횟수 | Belief Updating이 실제 발생했는지 확인 |
| `selected_exhibit_sources[]` | 최종 핵심 사료 선택 | 어떤 근거가 학생에게 핵심으로 인식되는지 수업 개선 |
| `completion` | S7 완료 여부 | 수업 시간 내 완결성 확인 |

> 운영 저장 판정은 **SAVE `required` / DASH `A`**로 잠근다. 교사가 수업 후 `어떤 보조자료를 열었는지`, `판단을 수정했는지`, `최종 핵심 사료를 무엇으로 골랐는지`를 확인할 교육적 이유가 있기 때문이다. 다만 **학생이 직접 쓴 자유서술 원문은 기본 서버 저장 대상에서 제외**하고, 선택 ID·관계 라벨·수정 횟수·완료 여부 등 구조화된 값만 저장한다. 저장 실패는 게임 완료를 막지 않는다.

## 12. 구현 금지 / 변경 금지

- S0을 2분 이상의 세계관 설명 컷신으로 늘리지 않는다. **첫 60초 안에 문장 표시 조작이 있어야 한다.**
- `석도=독도`를 칙령 원문의 직접 문구처럼 괄호 삽입하지 않는다.
- S3에서 근거 없이 `다른 섬 가능성`을 동등한 정답 후보로 제시하지 않는다.
- A15를 근거로 `군사적 고려가 편입의 직접 원인/촉진 요인`이라고 사실형 판정하지 않는다.
- S4의 관계 선택은 `직접 원인 / 배경 맥락 / 관계 강도 보류` 범위를 넘겨 단일인과를 강요하지 않는다.
- S5를 새 객관식 문제로 대체하지 않는다. **반드시 S3의 이전 메모를 재노출해 실제로 수정**하게 한다.
- S6에서 자료 카드 자유배치를 핵심 메커니즘으로 만들지 않는다. 시간축은 고정하고 관계 판단을 중심에 둔다.
- S7에서 2~3문장 전체 자유 타이핑을 필수로 요구하지 않는다. 게임 중 만든 문장 블록을 재사용한다.
- Visual Novel 대사를 장문의 지식 설명으로 사용하지 않는다.
- 사실층 오답과 해석층 차이를 동일한 빨간 X/초록 체크 체계로 처리하지 않는다.
- 현대 국제법적 영유권의 최종 판결을 게임 엔딩 정답으로 만들지 않는다.
- 캐릭터 호감도, 국가별 도덕 점수, 전쟁 승패 점수, 속도 보너스를 추가하지 않는다.

### 사료량

- 보조 사료: 약 30~60초 읽기 분량. 질문과 관련된 문단을 충분히 제공한다.
- `최소 발췌`를 목표로 하지 않는다. 문서의 목적과 논리를 이해할 만큼 제공한다.

### 모든 학생이 읽는 핵심 사료 4묶음
1. 1905 일본 내각 결정
2. 1877 태정관 지령 + 기죽도약도
3. 1900 의정부 청의서 일부 + 칙령 제41호 제1·2조
4. 1906 심흥택 관련 보고 + 의정부 지령 제3호

### 선택 조사 자료
- 현재 일본 외무성의 1905년 설명
- 나카이 요자부로 청원
- 시마네현 고시 제40호
- 군함 니타카 행동일지
- 군함 쓰시마 전시일지
- 현대 지명 연구
- 1904~1905 맥락 연표

### 선택 조사 규칙
- 보조자료는 전부 열람하지 않는다.
- 학생은 `현재 근거로 판단` 또는 `자료 하나 더 조사`를 선택한다.
- 읽지 않은 자료는 S6 연구 보드에 나타나지 않는다.
- 읽지 않은 자료 자체로 감점하지 않는다. 단, 최종 주장에 필요한 근거를 열지 않았다면 `현재 읽은 자료로는 이 표현이 강하다`는 피드백을 준다.

### 장면 수정
- S1: 1905 내각 결정을 정독한 뒤 현재 일본 정부 설명·나카이 청원·시마네현 고시는 선택 열람.
- S3: 칙령 제41호 뒤 니타카·현대 지명 연구·시마네현 고시 중 0~2개 선택. `추가 근거 필요` 상태로 그냥 진행 가능.
- S4: 나카이 청원·쓰시마 전시일지·러일전쟁 맥락 연표를 선택 조사. 모두 누르는 구조 금지.
- S5: 심흥택·의정부 지령은 핵심. S3에서 니타카를 읽지 않은 학생에게만 `1904 명칭 자료를 지금 확인` 선택 제공.
- S6: 실제 열람한 자료만 보드에 표시.

### 시간
- 게임 목표: 30~35분
- 내용 축소로 시간을 맞추지 않는다.
- 읽기 지원과 선택 조사로 학생별 경로 차이를 허용한다.

## 16. TECH / REPO INTEGRATION LOCK

### 현재 저장소 기준 구현 계약
- 저장소: `gtmc-history/games`
- 기본 기술: vanilla HTML/CSS/JS, GitHub Pages 정적 실행
- canonical identity: `folder slug = manifest slug = public URL slug = saved game identifier`
- 새 게임은 manifest에 **`draft`부터 등록**하고, 구현·테스트·배포 gate를 통과한 뒤에만 상태를 올린다.
- canonical title: `독도연구소: 1905 파일`
- canonical slug: `dokdo-1905-file`
- public URL(향후 published 시): `https://gtmc-history.github.io/games/dokdo-1905-file/`
- SAVE: `required`
- DASH: `A`
- renderer: `generic` 우선. 실제 운영 대시보드에서 구조화된 선택·수정 궤적을 읽는 데 generic으로 부족하다는 검증이 있기 전에는 custom renderer를 만들지 않는다.
- aliases: `[]`
- era 제안값(구현 manifest): `근대·국권침탈·독도`

### 권장 manifest 초안
```json
{
  "slug": "dokdo-1905-file",
  "title": "독도연구소: 1905 파일",
  "era": "근대·국권침탈·독도",
  "status": "draft",
  "save": "required",
  "dashboard": "A",
  "renderer": "generic",
  "aliases": []
}
```

### 권장 파일 구조
게임의 자료량·상태가 단순 단일 HTML 수준을 넘으므로 아래처럼 분리한다.
```text
dokdo-1905-file/
  index.html
  style.css
  app.js
  data.js
  assets/
    sources/
    ui/
```
프레임워크·npm runtime 의존성을 새로 추가하지 않는다.

### 저장 payload 잠금
최상위는 현재 `game_results` 공통 계약을 따른다.
```js
{
  class: CLASS,
  game: 'dokdo-1905-file',
  choices: {
    result_id,
    course_lens,
    evidence_seen,
    hint_used,
    revision_count,
    seokdo_status,
    context_relation,
    board_links,
    selected_exhibit_sources,
    completion
  },
  comment: '',
  timestamp: new Date().toISOString()
}
```
- `result_id`는 한 시도의 안정적 식별자로 권장한다.
- `initial_marked_phrase`, 학생 자유 편집문, 기타 자유서술 원문은 기본 서버 저장에서 제외한다. 필요하면 세션 안에서만 결과 화면 생성에 사용한다.
- 저장은 fire-and-forget 원칙을 지키며 네트워크 실패·HTTP 오류를 catch하고, 실패 때문에 엔딩 진입을 막지 않는다.
- 중복 제출 guard를 둔다.
- 클라이언트에는 secret/service-role/admin token을 넣지 않는다.

### 태블릿/모바일 잠금
- 터치 타깃 약 48×48px 이상
- 본문 16px 이상, 선택지 17px 이상, 제목 22px 이상
- hover-only 기능 금지
- 긴 핵심 사료는 정상 스크롤 허용
- 본문 구절 선택은 정밀 드래그만 요구하지 말고 `문장/구절 단위 탭 선택`을 지원한다.
- Evidence Board 관계 지정은 `자료 A 탭 → 자료 B 탭 → 관계 라벨` 방식으로 동작 가능해야 한다.

## 17. BUILD 전 남은 자산 blocker

다음은 설계 blocker가 아니라 **정식 자산 blocker**다. 해결되지 않은 상태에서 임시 텍스트나 가짜 이미지를 최종 자산처럼 취급하지 않는다.

1. **A15 쓰시마 전시일지**: JACAR `C09050402800` 안에서 실제 게임에 사용할 정확한 프레임/이미지 번호를 현재 뷰어에서 수동 확인한다.
2. **기죽도약도**: S2에서 실제 크롭을 사용하고, 학생이 위치·명칭 단서를 실제로 선택할 수 있도록 한다. 이 자산이 없으면 S2를 구현 완료로 보지 않는다.
3. **각 사료 이미지 이용조건**: JACAR·대한민국 외교부·일본 외무성 등 원 소장/제공처별로 게임 내 이미지 재사용 가능 범위와 표기 요건을 확인한다.
4. 사용권이 불확실한 이미지는 정식 빌드에 복제하지 말고, 출처 링크 + 자체 제작 전사/도식으로 대체 가능한지 별도 판단한다.

## 18. 구현 완료 판정

- `draft` 등록만으로 구현 완료가 아니다.
- S0~S7 전체 핵심 동선이 실제로 작동하고, S2 실제 지도 상호작용과 S5 과거 메모 수정이 구현되어야 `implemented` 후보가 된다.
