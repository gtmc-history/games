### v1 → v2 교체 사유

v1은 학생이 도시 변화의 원인을 지도 위 인과선으로 구성하는 Evidence Board 게임이었다. 실제 지도와 조작 노드를 결합하는 과정에서 지도 자체가 Gameplay를 과도하게 떠맡았고, 역사 지도·현대 지도·조작 좌표의 관계가 흔들렸다. v2는 지도 문제를 좌표 보정으로 해결하지 않고 **지도/철도도를 조사 문서로 되돌리고, 학생이 같은 원고를 새 자료에 따라 고쳐 쓰는 행위**를 Primary Gameplay로 전환한다.

v1의 기존 코드와 시각 패치는 v2 설계의 정본이 아니다. 참고 가능한 것은 기술 계약과 검증된 역사 자료뿐이다.

## 1. GAME DESIGN LOCK

### Historical Discovery

> 같은 철도망 안에서도 도시의 변화는 같지 않았다. 기존 도시의 지위, 철도, 행정 기능, 개항과 항만, 그리고 변화가 일어난 시점을 함께 보아야 각 도시의 서로 다른 변화 경로를 설명할 수 있다.

### 3행 설계 게이트

- **발견 한 문장**: 도시 변화는 철도 하나의 규칙으로 설명되지 않으며 도시마다 조건과 시점이 달랐다.
- **플레이 동사**: **조사한다 · 대조한다 · 고쳐 쓴다**.
- **행동의 이유**: 자신이 작성한 도시 변화 설명이 새 자료와 반례 때문에 흔들리므로, 자료에서 근거를 찾고 같은 문장을 계속 수정해야 한다.

### Player Verb

- 조사한다
- 대조한다
- 고쳐 쓴다

`넘긴다`, `확대한다`, `대사를 읽는다`는 인터페이스 동작이며 Player Verb가 아니다.

### Core Sequence

유형: **Sequence**

`익명 조건으로 첫 원고 작성 → 대전·공주 자료 조사 → 시간차로 1차 교정 → 이리에 현재 설명 적용 → 나주 반례 3단계 공개 → 2차 교정 → 목포에 현재 설명 적용 → 개항/철도 시점 충돌 → 최종 교정 → 최초 원고와 대조`

사례 내부 미니 루프:

`자료 열기 → 근거 구절 밑줄 → 주장에 클립 → 유지/조건 추가/범위 좁히기/시기 수정/유보/철회 → 교정본 제출`

### Game Fit

- 이 주제를 게임으로 만드는 이유: 핵심이 도시 성장 원인을 읽는 것이 아니라 **자기 설명이 반례 때문에 무너지고 다시 구성되는 과정**이기 때문이다.
- 활동지보다 적합한 이유: 첫 원고를 잠가 보존하고, 자료 도착 순서를 통제하고, 이전 문장을 다음 사례에 그대로 들고 가게 하며, 최종적으로 실제 수정 이력을 되돌려 줄 수 있다.

### Engagement Hook

1. `내가 처음 쓴 한 문장이 마지막까지 살아남을까?`
2. `대전과 이리에서 맞아 보인 철도 설명이 왜 나주에서 흔들릴까?`
3. `목포에서는 왜 철도보다 먼저 나타난 조건을 봐야 할까?`

### Primary Mechanic

**Narrative Investigation**

학생은 자료를 조사하고, 새 증거와 반례에 따라 자신의 작업 가설을 갱신한다.

### Secondary Mechanic

- **Document-driven Gameplay** — 문서 자체가 주요 조작 오브젝트다.
- **Minimal Belief Updating** — 확신도 수치 없이 유지/수정/유보/철회 이력을 남긴다.
- **Argumentation 요소** — 주장에 근거를 붙이고 직접 진술 여부를 구분하지만 정답식 논증 퍼즐로 만들지 않는다.
- **Progressive Disclosure** — 특히 나주 사례에서 자료를 3차례 나누어 공개한다.

### Presentation Layer

**Visual Novel + Document Desk + 빨간펜 교정 원고 + 역사 지도/철도도/연표**

Visual Novel은 Presentation Layer다. 상황 전환, 자료 도착, 반론 질문만 맡으며 역사 설명을 대신하지 않는다.

### Signature

**한 장의 원고가 반례를 만날 때마다 실제 교정 흔적을 남기며 변한다.**

포트폴리오 중복 회피:
- `대한신문 1907`: 정보 → 기사 선택 → 1면 제작 / Editorial Simulation
- `도시의 자리 v2`: 자료 조사 → 같은 문장에 근거 부착 → 반례 → 문장 교정 → 다음 사례에서 재시험 / Narrative Investigation
- 기존 Narrative Investigation의 대표 Signature가 Evidence Board인 것과 달리, 이 게임의 Signature는 **교정 원고의 diff**다.

### Replayability

불필요.

고정된 자료를 여러 번 소비하는 게임이 아니라 자신의 설명 변화가 산출물이다. 단, 재시작은 정상 동작해야 한다.

## 2. 시스템 LOCK

### 핵심 오브젝트: 작업 원고

플레이 내내 같은 원고 한 장을 유지한다.

원고 구성:
1. **현재 주장** — 도시 변화에 대한 학생의 현재 설명
2. **붙인 근거** — 문서에서 밑줄 친 구절을 주장에 클립
3. **미해결 메모** — 직접 인과가 확인되지 않은 연결에 `?`
4. **교정 흔적** — 조건 추가, 범위 축소, 시기 수정, 철회가 빨간 교정 표시로 남음

### 교정 조작 — 4종

1. **밑줄 긋기** — 자료 안의 사실/요약 구절을 선택
2. **클립하기** — 선택 구절을 주장 블록에 붙임
3. **빨간펜 교정** — 유지 / 조건 추가 / 범위 좁히기 / 시기 수정 / 철회
4. **? 남기기** — 직접 인과를 확인하지 못한 관계를 유보

자유 워드프로세서는 만들지 않는다. 중간 장면의 교정은 터치 중심으로 한다.

### State Variables

| key | 의미 |
|---|---|
| `initialPrediction` | 지명 공개 전 A/B 첫 판단 |
| `initialLead` | 지명 공개 전 첫 설명 원문. 이후 수정 불가 |
| `currentDraft` | 현재 원고의 주장 구조 |
| `claimBlocks` | 현재 살아 있는 주장 단위 |
| `evidenceMarks` | 문서에서 학생이 선택한 근거 구절 ID |
| `evidenceAttachments` | 주장↔자료 연결 |
| `openQuestions` | 끝까지 단정하지 않은 연결 |
| `revisionHistory` | 장별 교정 스냅샷 |
| `evidenceSeen` | 현재까지 공개된 자료 |
| `finalModel` | 마지막 자유 서술 |
| `scene` | 현재 씬 |

### `claimBlocks` 스키마

```text
{
  id,
  caseId,
  text,
  relationStatus: "해석으로 유지" | "자료에 직접 진술" | "유보" | "철회",
  evidence: [sourceId],
  timeScope: string | null
}
```

규칙:
- `자료에 직접 진술`은 해당 자료가 그 관계까지 직접 말할 때만 사용한다.
- 사실 A와 사실 B가 함께 존재한다는 이유만으로 A→B를 직접 인과로 승격하지 않는다.
- 새 자료가 와도 이전 교정 흔적은 삭제하지 않는다.

### 사용하지 않는 State

- 역사 이해 점수
- 도시 성장 점수
- 철도 영향력 % / 행정 영향력 % / 항만 영향력 %
- 확신도 0~100
- 정답 연결 개수
- 검열 위험 게이지
- 실제 마감 카운트다운

마감은 서사적 프레임일 뿐 시간 압박 메커닉이 아니다.

## 3. Meaningful Choice / Consequence LOCK

### 학생이 선택하는 것

새 자료가 들어올 때 현재 원고의 주장을:
- 그대로 유지한다
- 다른 조건을 추가한다
- 일반화 범위를 좁힌다
- 적용 시기를 좁힌다
- 인과를 유보한다
- 철회한다

### 선택 전 판단 정보

- 해당 시점까지 공개된 자료
- 학생이 현재 붙인 근거
- 직전 교정본
- 자료가 관계를 직접 진술하는지 여부

### 선택 간 실질적 차이

- 다음 사례로 가져가는 `currentDraft`가 달라진다.
- 동일 자료를 보더라도 어떤 기존 주장과 충돌하는지가 달라진다.
- 최종 화면의 교정 궤적과 `openQuestions`가 달라진다.

### Consequence

- **즉시**: 문장 diff, 근거 클립, `?` 표시 변화
- **지연**: 이전 설명이 다음 도시의 자료와 충돌하거나 강화됨
- **최종**: `초고 → 대전·공주 → 나주 → 목포 → 최종 원고` 비교

### Fail Forward

첫 판단이 틀렸거나 과도하게 일반화되어도 실패 화면을 띄우지 않는다. 반례를 만난 뒤 고쳐 쓸 수 있게 한다.

### 위장 객관식 방지

- 하나의 정답 문장을 고르는 구조로 만들지 않는다.
- 자료에서 근거를 골라 현재 주장에 붙이는 행동과 교정 행동을 분리한다.
- S1과 S7 외에는 긴 자유 입력을 요구하지 않는다.

## 4. 역사적 불변 원칙

1. 학생의 선택으로 실제 철도 개통, 개항, 도청 이전, 도시 위상 변화가 달라지지 않는다.
2. 학생이 바꾸는 것은 자신의 **설명, 근거 부착, 적용 범위, 적용 시기, 유보 상태**다.
3. 도시 성장과 식민지적 수탈 구조를 동일한 의미의 ‘발전’으로 처리하지 않는다.
4. 자료가 인과를 직접 말하지 않으면 시스템이 이를 `자료에 직접 진술`로 승격하지 않는다.
5. 상관·동시발생·시간적 선후를 임의로 인과로 만들지 않는다.
6. 지도/철도도는 위치·노선·공간 관계를 확인하는 자료이며, 지도 자체가 인과를 말하게 만들지 않는다.

### 학생 행동이 바꿀 수 있는 것

- 자기 설명의 구성
- 어떤 자료를 근거로 붙이는지
- 일반화 범위
- 적용 시기
- 판단 유보 여부

### 바꾸면 안 되는 실제 역사

- 1905 대전역 개통
- 1914 호남선 개통
- 1932 충남도청 공주→대전 이전
- 1912 호남선·군산선의 이리 지역 철도 연결
- 1896 전남 관찰부 설치 후 광주의 행정 중심화
- 1897 목포 개항
- 1914 목포까지 호남선 전 구간 개통
- 1932 목포의 시역 확대와 대도시 위상

### 후견지명 차단

- S1에서 지명·철도·지도 노출 금지.
- S2 이후에는 해당 장까지 필요한 자료만 공개.
- 목포의 1897 개항 자료는 철도 자료보다 먼저 공개하여 시간 선후를 학생이 확인하게 한다.
