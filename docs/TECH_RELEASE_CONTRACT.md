# TECH & RELEASE CONTRACT v1.2

이 문서는 기술 방향의 **불변 원칙**을 정의한다.
구체적 endpoint, key, 프로젝트 ID, 함수명, manifest 필드는 현재 저장소·DB·운영 환경을 확인한다.

## 1. 기본 환경

- Chromebook/태블릿 우선
- 모바일 반응형
- 로그인 없는 구조 우선
- GitHub Pages 정적 배포 우선
- 기본 플레이는 학습지 없이 완결
- 외부 API 실패가 보조 기능 때문에 핵심 플레이를 막지 않음

AI 대화 등 외부 API가 Primary Mechanic이면 DESIGN_LOCK에:
- 핵심 의존성
- 실패 시 재시도
- 대체 활동
- 사용자 안내

를 기록한다.

---

## 2. 파일 구조

기본:
`<game-folder>/index.html`

복잡한 경우 같은 게임 폴더 내:
- CSS
- JS
- data

분리 가능.

피한다:
- 이유 없는 프레임워크
- npm/build 없이는 실행 불가능한 구조
- 단순 게임의 과도한 파일 분리

핵심은 단일 파일이 아니라 이식성과 유지보수성이다.

---

## 3. 기술 SSOT

현재 사실은 다음 순서로 확인한다.

- 게임 목록/slug/status → 현재 canonical manifest
- 설계 의도 → 최신 DESIGN_LOCK
- 구현 → 현재 코드
- 저장/API/대시보드 → 현재 코드·스키마·운영 환경
- 과거 운영 정보 → archive

archive 값을 현재 계약으로 자동 복원하지 않는다.

---

## 4. 태블릿 UX

권장:
- 터치 타깃 약 48×48px 이상
- 본문 16px 이상
- 선택지 17px 이상
- 제목 22px 이상
- hover-only 기능 금지
- 필요한 자료 읽기는 스크롤 허용

---

## 5. 선택 UI

- 보통 4개 이하, 그러나 역사적 이유 없이 4지선다를 강제하지 않음
- 사실형과 판단형 피드백 구분
- 판단형 결과는 점수보다 패턴·궤적·누적 결과 우선

---

## 6. 데이터 저장

구현 전 현재 저장소 표준을 확인한다.

불변 원칙:
- game 식별자는 canonical registry와 일치
- 중복 전송 방지
- 네트워크 실패 catch
- fetch의 HTTP 오류 확인
- 전송 실패로 게임 진행 중단 금지
- 결과와 자유 소감의 분석 의미를 구분
- 수집 목적이 없는 데이터는 저장하지 않음
- 이름·학번 등 불필요한 개인정보 입력 유도 금지

---

## 7. 비밀값

- secret/service-role/admin token을 클라이언트에 넣지 않는다.
- 실제 비밀값을 문서에 기록하지 않는다.
- 공개 가능한 키도 문서에 영구 고정하기보다 현재 환경에서 확인/주입하는 방식을 우선한다.

---

## 8. 배포 체크

현재 저장소 기준으로 확인:
- manifest 등록
- game ID/slug 일치
- 허브 노출
- 저장 결과
- dashboard renderer
- 분석 집계
- 소감 처리
- analytics 정책
- 저작권 표기
- JS 문법
- 태블릿/모바일
- 재시작
- 네트워크 실패
- 회귀 테스트

구체적인 ID·필드·키 값은 현재 코드가 정본이다.

---

## 9. archive 사용

`archive/TECH_SNAPSHOT_2026-08-21.md`에는 과거 실코드 전수검증에서 확인된 계약이 보존되어 있다.

새 게임이나 마이그레이션에서 참고할 수 있으나:
1. 현재 코드와 대조
2. 여전히 유효한지 확인
3. 확인된 계약만 현재 구현에 사용

한다.
