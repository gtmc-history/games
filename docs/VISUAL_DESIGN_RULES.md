# VISUAL DESIGN RULES v1.1

## 1. 상위 원칙

디자인은 시대 장식보다 **역할·자료·Player Verb·Gameplay 기능**에서 출발한다.

UI는 다음 행동을 강화해야 한다.
- 사실 확인
- 추론
- 해석
- 평가
- 의사결정
- 협상
- 편집
- 조사

---

## 2. AI Slop 방지

피한다:
- 이유 없는 SaaS형 보라색 그라데이션
- 큰 둥근 카드의 반복
- 모든 요소의 과한 shadow
- 아이콘 + 제목 + 설명 카드의 기계적 반복
- 시대·역할과 무관한 기본 파란 버튼
- 무의미한 “시작하기 / 다음으로”
- 장르를 이유로 자동 타이머·점수·게이지 삽입

특정 폰트 이름을 영구 금지하는 것이 목적은 아니다.
문맥 없이 기본 템플릿을 복제하는 것을 피하는 것이 목적이다.

---

## 3. 버튼은 실제 행동을 말한다

권장:
- 자료를 대조한다
- 편집회의로 보낸다
- 이 판단을 유지한다
- 지도를 넓혀 본다
- 조건을 다시 확인한다

“다음”이 실제 의미 있는 행동이 아니라면 구체적 동사로 바꾼다.

---

## 4. 역할과 자료에서 화면 문법 도출

예:
- 편집자 → 원고, 교정지, 신문 지면
- 관리 → 결재 문서, 인장, 처리함
- 조사관 → 사건 파일, 증거 보드
- 외교관 → 전보, 조약 초안, 지도
- 현대 탐구자 → 명료한 분석 UI + 역사 자료 레이어

시대풍 장식을 씌우는 것만으로 디자인을 끝내지 않는다.

---

## 5. Diegetic UI

게임 세계 안의 물건이 실제 기능을 가질 때 사용한다.

좋음:
- 신문 제목을 실제 편집
- 조약 문구를 실제 수정
- 지도에서 실제 정보 범위를 확대
- 문서에 실제 분류 표시

나쁨:
- 기능 없는 낡은 종이
- 클릭할 수 없는 장식 문서
- 실제 플레이와 무관한 도장 애니메이션

---

## 6. Visual Novel

용도:
- 관계 소개
- 상황 전환
- 갈등 제시
- 자료 도착
- 판단을 되묻는 대화

피할 용도:
- 교과서 내용을 캐릭터가 대신 읽기
- 대화 사이 객관식만 삽입
- 플레이 시간 늘리기

Visual Novel 아래 실제 Gameplay Mechanic이 있어야 한다.

---

## 7. 피드백

### 사실형
명확한 정오 피드백 가능.

### 해석/평가/의사결정
정답/오답 대신:
- 조건
- 대가
- 한계
- 새 정보
- 판단 패턴
- 선택됨 상태

를 사용한다.

---

## 8. 결과 화면

판단형 게임은 점수보다:
- 선택 궤적
- 판단 변화
- 중요하게 본 기준
- 끝까지 남은 불확실성
- 만든 결과물

을 보여주는 것을 우선한다.

---

## 9. 태블릿

권장:
- 터치 타깃 최소 약 48px
- 본문 16px 이상
- 선택지 17px 이상
- 제목 22px 이상
- hover에만 의존하지 않음
- 가로 Chromebook/태블릿에서 우선 검수
- 필요한 자료 읽기는 자연스러운 스크롤 허용

---

## 10. 시대 디자인

시대 팔레트는 강제 스킨이 아니라 참고 레이어다.

현대 탐구자 + 역사 자료 구조라면:
- 현대 조작부: 중립·명료
- 역사 자료: 문서 문법·연도·출처를 강조

모든 화면을 세피아로 만들 필요가 없다.

시대별 팔레트·애니메이션 예시는 `VISUAL_REFERENCE_LIBRARY.md`를 참고한다.
