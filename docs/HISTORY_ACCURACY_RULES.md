# HISTORY ACCURACY & EVIDENCE RULES v1.1

전 시대 공통 역사 정확성·사료·인과 규칙.

## 1. 사실 / 해석 / 평가

### 사실
교과서·사료·연구로 확인 가능한 정보.
명확한 정오 피드백 가능.

### 해석
자료를 연결하고 의미를 설명하는 층.
복수 해석이 성립하면 정답/오답으로 칠하지 않는다.

### 평가
중요성·효과·책임·한계 등을 기준과 근거로 판단하는 층.

피드백 방식은 게임 장르가 아니라 각 행동의 층으로 결정한다.

---

## 2. 근거 등급

### A — 직접 근거
- 원사료
- 법령 원문
- 당시 통계
- 신뢰 가능한 학술 연구에서 직접 확인한 사실

### B — 교육적으로 사용 가능한 2차 근거
- 검증된 교과서
- 공신력 있는 기관 자료
- 신뢰 가능한 개설서·연구 정리

### C — 미확인 / 탐색 단서
- 출처 미확인 요약
- 블로그·커뮤니티
- AI 생성 설명
- 원문을 확인하지 못한 2차 인용

C를 게임의 확정 사실로 사용하지 않는다.

---

## 3. 출처와 게임 사용을 분리 기록

중요 주장에는 가능하면 DESIGN_LOCK에:
- 주장
- 출처
- 등급
- 게임 내 사용 방식
- 과잉해석 금지선

을 기록한다.

기각한 자료도 중요한 경우 이유를 남긴다.

---

## 4. 후견지명 차단

당대에 알 수 없던 결과를 선택지에 미리 넣지 않는다.

필요하면:
- 해당 시점까지의 정보만 제공
- 이후 실제 사건은 학생 선택과 무관하게 발생
- 사건 이후 이전 판단을 재검토

구조를 사용한다.

---

## 5. 역사 사건과 플레이어 선택의 인과

학생 선택 때문에 실제 역사 사건이 생긴 것처럼 만들지 않는다.

잘못:
“외교를 골랐기 때문에 실제 전쟁이 일어났다.”

가능:
“당시 외교를 우선했다. 이후 실제 사건이 발생했다. 그 사건을 본 뒤 이전 판단을 재검토한다.”

---

## 6. 가공 인물

가공 인물은 사용할 수 있다.

단:
- 직업·계층·지역·정보 접근성·선택 범위가 당시 자료로 설명 가능해야 한다.
- 실제 인물이 하지 않은 말을 실제 발언처럼 쓰지 않는다.
- 존재하지 않은 사건을 사실처럼 만들지 않는다.
- 근거 자료를 DESIGN_LOCK에 기록한다.

민감 주제의 대표성 문제는 `SENSITIVE_HISTORY_RULES.md`를 추가 적용한다.

---

## 7. 수치·확률

집계 통계를 개인 확률로 변환하지 않는다.

예:
“신청 676건 중 556건 허가”
→ “당신의 허가 확률 82.2%”로 바꾸지 않는다.

게임 자원·게이지도 실제 역사 수치처럼 보이면 근거가 필요하다.

---

## 8. 불확실성

사료가 충돌하거나 연도·동기·인과가 불확실하면 억지로 하나의 정답으로 만들지 않는다.

가능한 Gameplay:
- 기록 불일치
- 판단 유보
- Confidence Meter
- 추가 자료 요청
- 출처 비교
- Contradiction Detection

---

## 9. 정오 피드백

정답/오답 피드백은 게임 안의 정보·교과서·사료로 정오를 판별할 수 있는 사실형 행동에만 사용한다.

해석·평가·의사결정에는:
- 선택됨
- 조건
- 대가
- 한계
- 새 정보
- 판단 패턴

을 제시한다.

---

## 10. 역사적 인과를 게임 시스템으로 만들 때

상관관계·동시발생·후속 결과를 임의로 인과관계로 바꾸지 않는다.

상태 변수와 규칙을 만들 때 질문한다.

- 이 관계는 자료가 직접 뒷받침하는가?
- 방향성이 확인되는가?
- 개인 수준인지 집단 수준인지 구분했는가?
- 정량화가 가능한가?
- 단순화를 했다는 표시가 필요한가?

근거가 약하면 관계를 시스템으로 구현하지 않고 설명·자료 비교로 남길 수 있다.
