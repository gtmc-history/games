# 독도연구소: 1905 파일 — BUILD QA CHECKLIST

이 문서는 `DESIGN_LOCK v1.0`을 바꾸기 위한 문서가 아니라, 현재 BUILD가 잠긴 설계를 실제 브라우저에서 제대로 구현했는지 확인하기 위한 실기 체크리스트다.

## 0. 테스트 원칙

- production `game_results`에 테스트 행을 넣지 않는다.
- 저장 검증은 DevTools fetch intercept, mock, 승인된 test 환경 중 하나를 사용한다.
- 실제 학생 화면에 내부 A/B 등급, source ID, JACAR ref, QA 용어가 튀어나오지 않는지 확인한다.
- 역사 판단을 바꾸지 않고 **화면 이해 가능성 / 동작 가능성 / 상태 보존 / 저장 계약**을 검사한다.

## 1. 시작·공통 UI

- [ ] `/dokdo-1905-file/?class=test` 직접 진입 시 게임이 열린다.
- [ ] 모바일 390px, 태블릿 768px, 데스크톱 1280px에서 가로 스크롤이 생기지 않는다.
- [ ] 시작 화면에서 게임 목표가 20초 안에 이해된다.
- [ ] 한국사/동아시아사 렌즈가 선택 가능하고 선택 결과가 세션에 유지된다.
- [ ] 최소 VN을 켠 상태에서 대화가 사료 정답을 미리 말하지 않는다.
- [ ] VN을 건너뛰거나 재개해도 핵심 Gameplay 상태가 깨지지 않는다.
- [ ] 새로고침 후 sessionStorage 복원이 가능한 장면에서는 이전 선택이 복원된다.

## 2. S0 — 전시 초안 검수

목표: 첫 60초 안에 학생이 실제 조작을 시작한다.

- [ ] 가공 전시 원고가 역사 사료처럼 보이지 않고 `게임 속 가공 원고`임이 드러난다.
- [ ] 학생이 문제 표현을 직접 선택한다.
- [ ] 선택 전에 `정답 표현`이 강조되어 있지 않다.
- [ ] 표현 1개 + 조사 목적 1개를 선택해야 다음으로 진행된다.
- [ ] 이 첫 판단이 이후 결과 화면의 `처음 판단` 기록에 남는다.

## 3. S1 — 1905 내각 결정

목표: 학생이 `판단 근거`와 `실제 행정 결정`을 구분한다.

- [ ] 학생용 현대어 재구성이 충분한 분량으로 읽힌다.
- [ ] 원문 핵심구절이 별도 정보층으로 보이고 학생용 현대어와 섞이지 않는다.
- [ ] 현재 일본 정부의 `주권 재확인` 설명은 당대 결정문과 별도 선택자료로 존재한다.
- [ ] 최소 1개의 판단 근거 + 1개의 결정 구절을 선택해야 진행된다.
- [ ] 나카이 청원 / 현재 일본 정부 설명 / 시마네현 고시는 **전부 열지 않아도 진행 가능**하다.
- [ ] 선택하지 않은 보조자료는 이후 연구 보드에 나타나지 않는다.

## 4. S2 — 1877 태정관 지령

목표: `본문 직접 문구`와 `지도까지 연결한 식별`을 구분한다.

현재는 실제 기죽도약도 asset blocker가 남아 있으므로 두 단계로 검사한다.

### DEV placeholder 상태
- [ ] 화면에 `DEV PLACEHOLDER`가 명확히 표시되어 최종 사료 이미지로 오인되지 않는다.
- [ ] 본문의 `죽도 외 1도` 처리 내용을 먼저 확인한다.
- [ ] 지도 단서 2개를 확인하기 전에는 식별 메모가 활성화되지 않는다.
- [ ] 힌트를 써도 자동 정답 처리되지 않고 다음으로 무엇을 봐야 하는지만 알려준다.

### 실제 기죽도약도 asset 교체 후
- [ ] 국립공문서관 원 공개본을 사용한다.
- [ ] 크롭/강조를 했다면 가공 사실과 출처가 화면에 표시된다.
- [ ] 실제 지도에서 명칭·방향·상대 위치 단서를 클릭/탭할 수 있다.
- [ ] 모바일에서도 hotspot이 44px 이상 터치 가능 영역을 가진다.
- [ ] 지도 이미지를 보지 않고 단순 버튼 문구만 읽어도 답이 노출되는 구조가 아니다.

## 5. S3 — 1900 칙령 제41호

목표: `석도`를 원문 사실과 현재 지명 식별 문제로 분리한다.

- [ ] 제1조와 제2조의 내용이 학습에 충분한 분량으로 제시된다.
- [ ] 원문에는 `석도`라고 표시되고 학생 화면에서 자동으로 `(독도)`를 붙이지 않는다.
- [ ] 학생은 행정개편과 관할구역 구절을 각각 선택한다.
- [ ] 장면 종료 시 메모가 `현재 독도와의 연결: 추가 근거 필요` 상태로 저장된다.
- [ ] 이 메모가 S5에서 실제로 다시 등장한다.

## 6. S4 — 선택 조사

목표: 모든 자료를 누르는 전자교재가 아니라 필요한 자료를 골라 읽는 조사 경험이 된다.

- [ ] 니타카 / 지명연구 / 쓰시마 / 맥락 연표 중 0~4개를 자유롭게 고를 수 있다.
- [ ] 어떤 보조자료도 열지 않은 상태에서도 `관계 강도 보류`로 진행할 수 있다.
- [ ] 니타카를 열면 `누가 기록 / 정보 경로 / 명칭` 분해 조작이 열린다.
- [ ] 니타카 세 요소를 모두 확인한 경우에만 `한국인이 독도라고 적는다는 정보를 일본 군함이 기록`한 것으로 메모된다.
- [ ] 니타카 자료를 `대한제국 공식 명명 문서`로 표현하지 않는다.
- [ ] 쓰시마 자료를 열더라도 `러일전쟁 때문에 편입`으로 자동 결론내리지 않는다.
- [ ] `직접 원인이라고 주장`을 선택하면 진행을 막는 게임오버가 아니라 근거 범위 경고를 준다.
- [ ] 선택한 자료만 `evidence_seen` / 연구 보드에 남는다.

## 7. S5 — 1906 후속 기록 / Belief Updating

이 장면은 게임의 핵심 유지 조건이다.

- [ ] 심흥택 관련 보고에서 `본군 소속 독도`와 `일본 측 편입 통보`를 각각 학생이 표시한다.
- [ ] 의정부 지령에서 중앙정부의 대응을 학생이 표시한다.
- [ ] 충분한 1906 구절을 표시하기 전에는 1900 메모 수정 버튼이 비활성화되어 있다.
- [ ] 새 근거 트레이에 **이번 플레이에서 실제 확보한 단서만** 들어온다.
- [ ] S3의 옛 메모 문장이 그대로 다시 보인다.
- [ ] 학생이 `근거 보강 / 판단 보류`를 직접 선택해 과거 메모를 수정한다.
- [ ] 어떤 선택에도 `1900년 원문 표기는 석도`라는 주의가 남는다.
- [ ] `revision_count`가 실제 수정 행동과 맞게 기록된다.
- [ ] 학생이 이 장면에서 `새 자료 때문에 내가 이전 판단을 다시 검토했다`고 인식할 수 있는지 실기 관찰한다.

## 8. S6 — 연구 보드

목표: 자유 배치 놀이가 아니라 자료 관계를 판단하는 Gameplay가 된다.

- [ ] 실제 열람한 자료만 보드에 나온다.
- [ ] 연도 위치는 고정되어 있어 태블릿 드래그 부담이 없다.
- [ ] 핵심 사료는 2~4개만 선택할 수 있다.
- [ ] 관계선은 최대 3개만 저장된다.
- [ ] 서로 같은 자료를 A/B로 선택하면 추가되지 않는다.
- [ ] `보강 / 긴장 / 후속 대응 / 시대적 배경 / 직접 인과 단정 어려움`의 의미가 학생에게 이해된다.
- [ ] 관계를 삭제하고 다시 만들 수 있다.
- [ ] 최소 핵심자료 수와 최소 관계 수를 충족해야 S7로 진행된다.

## 9. S7 — 전시 패널

목표: 미리 준비된 모범답안을 편집하는 것이 아니라 **내가 실제 저장한 메모**를 재료로 쓴다.

- [ ] 선택하지 않은 자료의 문장은 최종 블록 목록에 나타나지 않는다.
- [ ] `extractedNotes + boardLinks`에서만 전시문 재료가 생성된다.
- [ ] 제목·본문·주의문 입력이 모바일에서 불편하지 않다.
- [ ] 자유서술을 서버 저장하지 않는다는 설계가 코드와 일치한다.
- [ ] 전시문에 `석도=독도 확정`, `러일전쟁이 유일한 원인` 같은 과잉 문구를 시스템이 자동 생성하지 않는다.
- [ ] 전시 확정 뒤 처음 판단 → 중간 메모 → 최종 판단 변화가 결과 화면에 보인다.

## 10. SAVE payload

브라우저 DevTools에서 `fetch`를 intercept하거나 mock endpoint로 전송해 확인한다.

필수 최상위:

```js
{
  class,
  game: 'dokdo-1905-file',
  choices: {...},
  comment,
  timestamp
}
```

`choices`에서 확인:

- [ ] `result_id`
- [ ] `version`
- [ ] `course_lens`
- [ ] `evidence_seen`
- [ ] `opened_optional`
- [ ] `hint_used`
- [ ] `revision_count`
- [ ] `seokdo_status`
- [ ] `context_relation`
- [ ] `board_links`
- [ ] `selected_exhibit_sources`
- [ ] completion 관련 구조화 값

저장 금지 확인:

- [ ] S7 자유서술 `finalPanel.title/body/caution` 원문이 payload에 없다.
- [ ] service-role key가 client에 없다.
- [ ] production DB INSERT 없이 검증했다.
- [ ] 네트워크 저장 실패 시 완료/엔딩 화면은 계속 열린다.
- [ ] 재시도 버튼은 저장만 재시도하고 게임 상태를 초기화하지 않는다.

## 11. 접근성·교실 사용

- [ ] 모든 `<button>`이 키보드 Tab으로 접근 가능하다.
- [ ] 선택 상태가 색만으로 구분되지 않는다.
- [ ] modal/dialog를 닫은 뒤 초점이 합리적인 위치로 돌아온다.
- [ ] 긴 원문·현대어 영역의 행간과 폭이 태블릿에서 읽기 가능하다.
- [ ] 35~40명 동시 사용 시 외부 사료 사이트 접속이 없어도 핵심 Gameplay가 진행된다.
- [ ] 외부 원문 링크 실패가 게임 진행을 막지 않는다.
- [ ] 첫 조작까지 실제 학생 기준 60초 이내인지 측정한다.
- [ ] 전체 플레이 중앙값 목표는 약 30~35분으로 측정하되, 내용 삭제로 시간 목표를 맞추지 않는다.
